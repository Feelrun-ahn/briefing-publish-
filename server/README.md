# Briefing 중계 서버 (Cloudflare Workers)

앱과 외부 서비스 사이에 두는 작은 서버입니다. **PC 에서 한 번만 배포하면 됩니다.**

## 무엇을 거치고 무엇을 안 거치나

| | 서버 경유 | 이유 |
|---|---|---|
| **시간표(나이스)** | ✅ | 인증키를 감춰야 하고 호출 한도가 있음 |
| **야구(TheSportsDB)** | ✅ | 지금은 모든 사용자가 공용 시험 키를 나눠 씀 |
| **뉴스(구글)** | ✅ | CORS 가 없어 공개 프록시에 기대고 있었음 |
| **날씨(Open-Meteo)** | ❌ | 키가 없고 CORS 를 허용함. **거치면 오히려 나쁨** |

**날씨를 서버로 보내면 안 되는 이유** — 지금은 사용자 각자의 기기에서 요청이 나가
자연히 분산됩니다. 서버를 거치면 모든 요청이 한 IP 에서 나가 차단될 위험이 커집니다.

## 서버가 하는 일

1. **키를 감춘다** — 키는 서버 환경변수에만 있고 앱에는 없습니다
2. **같은 요청을 묶는다** — 같은 학교·학년·반·주간을 100명이 동시에 물어도
   나이스에는 한 번만 갑니다 (in-flight deduplication)
3. **잠깐 저장한다** — 이번 주 시간표 30분, 지난 주 하루, 야구 시즌 6시간, 뉴스 30분
4. **한도에 걸리면 그대로 알린다** — 우회로를 찾지 않습니다
5. **너무 많이 부르면 막는다** — 한 IP 당 1분에 60번
6. **CORS 를 허용한다**

## 요청 제한이 왜 필요한가

무료 한도는 **하루 10만 요청**입니다. 봇 하나가 두들기면 그날 모두가 못 씁니다.
(무료 플랜은 넘어가면 그냥 멈추므로 **요금이 청구되지는 않습니다.**)

`RATE = { max: 60, win: 60_000 }` — 필요하면 이 값만 바꾸세요.

## 배포

```bash
npm i -g wrangler
wrangler login
wrangler secret put NEIS_KEY      # 나이스 인증키
wrangler secret put ADMIN_KEY     # 상태 페이지 비밀번호 (직접 정하기)
wrangler secret put SDB_KEY       # (선택) TheSportsDB 키
wrangler deploy
```

주소가 나오면 `js/neis.js` 맨 위 `API_BASE` 에 넣으세요.

```js
let API_BASE = 'https://briefing-api.내계정.workers.dev';
```

**넣기 전까지는** 야구·뉴스는 예전 방식으로, 시간표는 직접 넣기로 동작합니다.
앱이 깨지지 않습니다.

## 주소

| 주소 | 하는 일 | 저장 |
|---|---|---|
| `/health` | 살아 있는지 | — |
| `/admin?key=<ADMIN_KEY>` | **상태 보기 (화면)** | — |
| `/stats?key=<ADMIN_KEY>` | 상태 보기 (숫자만) | — |
| `/school?q=목운중` | 학교 검색 | 하루 |
| `/timetable?office=&school=&grade=&class=&from=&to=&kind=` | 시간표 | 이번 주 30분 · 지난 주 하루 |
| `/sports?path=eventsnext.php%3Fid%3D139825` | 야구 | 시즌 6시간 · 그 외 30분 |
| `/news?url=<구글 뉴스 RSS>` | 뉴스(JSON 으로 변환) | 30분 |

## 무료 한도와 비용

- 하루 10만 요청, 요청당 CPU 10ms, 요청당 외부 호출 50개
- 우리는 요청당 외부 호출 1~2개, CPU 는 기다리는 시간을 세지 않아 여유 있음
- **넘으면 멈출 뿐 청구되지 않음** — 카드 등록도 필요 없음

| 사용자 | 하루 요청 | 여유 |
|---|---|---|
| 1,000명 | ~3,000 | 3% |
| 10,000명 | ~30,000 | 30% |
| 30,000명 | ~90,000 | 한계 |

넘어가면 월 5달러 유료로 올리면 됩니다 (1,000만 요청 포함).

## 키를 GitHub 에 올리지 않으려면

`wrangler.toml` 에는 키를 적지 않습니다. `wrangler secret put` 으로 넣은 값은
Cloudflare 에만 저장되고 파일로 남지 않습니다. **이 폴더를 그대로 올려도 안전합니다.**

## 상태 페이지

```
https://briefing-api.내계정.workers.dev/admin?key=내가정한비밀번호
```

오늘 하루 이만큼을 보여 줍니다.

| 보이는 것 | 뜻 |
|---|---|
| **나이스 실제 호출** | 오늘 나이스로 나간 요청 (한도를 쓰는 것) |
| **저장해 둔 것으로 처리** | 나이스를 부르지 않고 답한 횟수 |
| **아낀 비율** | 캐시가 얼마나 잘 듣는지 |
| 야구 · 뉴스 | 각각의 중계 횟수 |
| **막은 요청** | 너무 자주 불러 거절한 횟수 (봇 감지용) |

색으로 알려 줍니다 — 나이스 호출이 4,000 넘으면 노랑, 8,000 넘으면 빨강.

### 왜 직접 세나

**나이스는 남은 한도를 알려 주는 방법이 없습니다.** 그래서 서버가 셉니다.

### 숫자가 0 으로 돌아간다면

Workers 는 한동안 요청이 없으면 잠들고, 깨어날 때 기억이 사라집니다.
숫자를 계속 남기려면 **KV 를 붙이세요** (무료, 5분).

```bash
wrangler kv namespace create USAGE
```

나온 `id` 를 `wrangler.toml` 에 넣고 다시 배포하면 됩니다.

```toml
[[kv_namespaces]]
binding = "USAGE"
id = "여기에-나온-id"
```

KV 무료 한도는 하루 읽기 10만 · 쓰기 1천이라 넉넉합니다.

### 주의

`ADMIN_KEY` 를 정하지 않으면 상태 페이지가 **항상 막힙니다.** 꼭 넣으세요.
비밀번호는 주소창에 들어가므로 남에게 보여 주지 마세요.
